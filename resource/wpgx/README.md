# resource/wpgx

```sh
go get github.com/ggsrc/gglib/resource/wpgx
```

A Postgres connection pool as a [resource](..). The pool comes from
[stumble/wpgx](https://github.com/stumble/wpgx), a wrapper around
[pgx](https://github.com/jackc/pgx) v5 with read-replica routing, Prometheus
metrics and tracing; code generated by the wpgx flavour of sqlc runs its
queries on it.

## Usage

```go
db := wpgx.NewWPGXWithDefaultEnvPrefix() // POSTGRES_* variables
// or: wpgx.NewWPGXWithOptions(wpgx.WithConfig(&cfg))

rm := resource.NewResourceManager([]resource.Resource{db})
// ... after rm.Init (or app.Init) succeeded:
pool := db.GetPool() // *wpgx.Pool
```

## API

| Name | What it does |
|---|---|
| `NewWPGXWithDefaultEnvPrefix()` | Configured from `POSTGRES_*`. An invalid configuration exits the process (wpgx's own behaviour). |
| `NewWPGXWithOptions(opts...)` | `WithConfig(cfg)` is required (panics without it); `WithBeforeAcquire(f)` sets a hook called before the primary pool hands out a connection. |
| `Init(ctx)` | Creates the pool and pings the primary and every replica. If `ctx` has no deadline, it waits at most `DefaultInitTimeout` (30 s), so an unreachable database cannot hang startup. On failure it closes the pool and returns the error, and can be called again. It does not modify the configuration it was given. A second call after success returns `wpgx: already initialized`. |
| `Start(ctx)` | Returns `wpgx: not initialized` before a successful `Init`; otherwise does nothing. |
| `Stop(ctx)` | Closes the pool, waiting for borrowed connections to be returned until `ctx` ends. Safe to call more than once. |
| `OK(ctx)` | Pings the **primary** only. A failed replica does not make the service unhealthy; queries routed to it fail, others succeed. |
| `GetPool()` | The pool; `nil` before `Init` and after `Stop`. |
| `Name()` | `"wpgx"`. |

`Init` logs the configuration (`wpgx: creating pool`, password shown as
`*hidden*`) and, on success, `wpgx: pool is ready` with the number of
replicas.

## Configuration (prefix `POSTGRES_`, defined by wpgx)

| Variable | Default | Meaning |
|---|---|---|
| `POSTGRES_HOST`, `POSTGRES_PORT` | `localhost`, `5432` | Primary address. |
| `POSTGRES_USERNAME`, `POSTGRES_PASSWORD` | `postgres`, `my-secret` | Credentials. The defaults are for local development only. |
| `POSTGRES_DBNAME` | `wpgx_test_db` | Database name. |
| `POSTGRES_APPNAME` | **required** | Application name, 1–32 characters; shows which client a connection belongs to on the server. |
| `POSTGRES_MAXCONNS`, `POSTGRES_MINCONNS`, `POSTGRES_MINIDLECONNS` | 20, 0, 0 | Pool size limits. |
| `POSTGRES_MAXCONNLIFETIME`, `POSTGRES_MAXCONNIDLETIME` | 6h, 1m | Maximum connection lifetime and idle time. |
| `POSTGRES_SSLMODE` | `disable` | TLS mode. |
| `POSTGRES_ISPROXY` | false | Set to true behind a connection pooler such as PgBouncer: pgx then uses an execution mode without cached prepared statements. |
| `POSTGRES_ENABLEPROMETHEUS`, `POSTGRES_ENABLETRACING` | true, true | Query metrics and spans. |
| `POSTGRES_REPLICAPREFIXES` | empty | Comma-separated prefixes of read replicas. For each prefix `P`, `P_NAME` (required, unique, different from the application name), `P_HOST`, `P_PORT` and the same set of variables are read. |

Variable names are the field names in upper case without separators:
`DBNAME`, not `DB_NAME`.

## Testing

[wpgx/testsuite](https://pkg.go.dev/github.com/stumble/wpgx/testsuite) starts a
Postgres container per test suite with Testcontainers;
from wpgx v0.5.1, `testsuite.WithPostgresImage("postgres:18.6")` selects the
version. Test against the major version your production database runs.
