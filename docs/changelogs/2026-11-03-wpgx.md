# fix(resource/wpgx): retryable Init, no leaks, bounded Stop, real-Postgres tests

Tracking: alva-ai/mono-meta#1115 (gglib, per-module PR). Stacked on #31.

## 1. Current state

Review (resources W4–W8, W11–W14, W16), proven:

- A failed `Init` set `initialized` and `sync.Once` returned nil on retry;
  `OK` was nil with no pool.
- A failed ping returned without closing the pool (goroutines and metric
  collectors leaked).
- `Init` set `BeforeAcquire` on the caller's config and logged it, which with
  wpgx v0.4.7 overwrote replica passwords (fixed by v0.5.0, wrapper still
  mutated the config).
- No deadline on `Init`; `Stop` ignored its context.
- `OK` pinged every replica, so one replica outage made every pod unready.
- The type loader had a data race, skipped replicas and had no users.
- No tests.

## 2. Behavior after this change

- `Init` works on a copy of the config, bounds itself with a 30 s timeout
  when the context has none, closes the pool on failure and can be retried.
  A second successful-state `Init` is an error.
- `Stop` closes the pool in the background and returns `ctx.Err()` if the
  context ends first; idempotent.
- `OK` pings the primary only (`PingPrimary`); `OK`/`Start` fail before
  `Init`.
- The type loader is removed; `gglib/zerolog` is no longer a dependency.

Consumer impact: alfs, alva-backend, worldline and llm-data construct the
resource the same way; none uses the type loader. PRD Postgres has no read
replicas today, so the `OK` change has no effect yet.

## 3. Decisions

- Primary-only health: a replica is an optimisation; its failure should
  degrade queries routed to it, not take every pod out of service.
- Type loader removal follows G1.
- `scripts/replaces.sh` now derives sibling replaces from the module graph
  and drops replaces that are no longer needed; resource/wpgx is the first
  module to lose its gglib dependencies.

## 4. Changes

- `resource/wpgx/wpgx.go`, `options.go` rewritten; `pool.go` and `types.go`
  deleted; `wpgx_test.go` with testcontainers v0.44.0 (Postgres 17).
- `scripts/replaces.sh`: graph-based add and drop.
- Coverage floors (`<module>/.coverage-floor`): resource/wpgx 0 → 100. `CHANGELOG.md`.

## 5. Verification

- `go test -race` in resource/wpgx against a real Postgres container: 100%
  coverage. Covers retry after a wrong password, config not mutated (with a
  replica entry and a password containing `@/#?`), `BeforeAcquire` runs,
  `Stop` returns at its deadline while a connection is held.
- `make tidy-check build vet test lint cover` — all 13 modules pass;
  `scripts/replaces.sh` is idempotent.
