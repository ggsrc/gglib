# fix(resource): stop everything, name errors, keep the caller's context

Tracking: alva-ai/mono-meta#1115 (gglib, per-module PR). Stacked on #31.
**The stop order is unchanged here and waits for decision G12** (reverse
order vs. today's registration order, which alfs and stream-relay rely on).

## 1. Current state

Review (lifecycle RES-1 … RES-6), proven:

- `Stop` returned at the first error, leaking later resources.
- `Start` handed resources an errgroup context canceled when `Start`
  returned; it ran in parallel; a failure stopped everything and printed to
  stdout with `fmt.Printf`.
- Errors carried no resource name; `OK` returned only the first failure.
- `AddResource` was not concurrency-safe; `HealthStatus` was dead code.
- No tests.

## 2. Behavior after this change

- `Init`: in order, first error returned with the resource name.
- `Start`: in order, with the caller's context; on failure, stops every
  resource and returns the start error joined with stop errors.
- `Stop`: every resource is stopped; errors joined and named; only the first
  call acts. **Order: registration order, as today (G12 pending).**
- `OK`: every failing resource reported, by name.

Consumer impact: alva-backend, alfs, worldline, stream-relay and llm-data
call `Init`/`Start`/`Stop`/`OK` the same way. alva-backend calls `Stop`
itself and through `app`; the second call is now a no-op. Error texts gain a
`resource <name>: <phase>:` prefix.

## 3. Decisions

- G12 open; `stopOrder()` is the single place to change.
- Sequential `Start`: matches `Init` order and makes failures
  deterministic. Every current `Start` is non-blocking.
