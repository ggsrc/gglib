# fix(mctx): exact numbers in Extras, size limit, remove wallet-era fields

Tracking: alva-ai/mono-meta#1115 (gglib, per-module PR). Stacked on #31.
Decision G7 = B (Yumin, 2026-11-03): keep sonic; fix only the number
precision and add a size limit.

## 1. Current state

- `Extras` numbers decoded as `float64`; IDs above 2^53 changed value after
  one hop (review M-1, proven). alva-backend stores API key, group actor,
  billing and lease IDs there.
- No size limit: a 10.7 MB header took 0.6–1.3 s and 84–136 MB to parse.
- `User` carried wallet-login fields (`Address`, `SignAt`, `Signature`,
  `AccessToken`, `JwtString`) and `LocationInfo` existed; none is used by any
  service (M-5).
- No tests.

## 2. Behavior after this change

- `StringToAppCtx` decodes with sonic `UseNumber`: numbers in `Extras` are
  `json.Number`, exact. Every reader in Alva handles this: alva-backend's
  `authctx.anyToInt64` has a `json.Number` case, and the other readers format
  the value with `%v`, which prints the exact digits.
- Input over `MaxAppCtxSize` (32 KiB) returns `ErrAppCtxTooLarge`. The
  server interceptor already treats a parse error as "no app context" and
  logs it.
- The wallet-era fields and `LocationInfo` are removed. JSON that still
  contains them parses; the fields are ignored.
- Unchanged by decision G7: sonic stays (v1.15.5 runs natively on Go 1.27;
  it falls back to encoding/json from Go 1.28), the caller-supplied `Now`
  and `IP` are taken as sent (documented; the trust model is G3), and
  `AppID` stays `int32`.

## 3. Decisions

- G7 = B.
- 32 KiB limit: an app context is a few hundred bytes; 32 KiB leaves room
  for large `Extras` while bounding parse time and memory.
- The fields were removed under G1 (unused code is removed before the first
  release).

## 4. Changes

- `mctx/app_ctx.go`: decoder with `UseNumber`, `MaxAppCtxSize`,
  `ErrAppCtxTooLarge`, trust-model doc.
- `mctx/user.go`: wallet-era fields removed; `mctx/location.go` deleted.
- `mctx/app_ctx_test.go`: table tests and an example; 100% coverage.
- `.github/coverage.txt`: mctx floor 0 → 100. `mctx/CHANGELOG.md`.

## 5. Verification

- `go test -race` in mctx: 100.0% coverage, including the precision case
  (1234567890123456789 and 9007199254740993 round-trip exactly) and the size
  boundary (exactly `MaxAppCtxSize` parses, one more byte is rejected).
- `make tidy-check build vet test lint cover` — all 13 modules pass.
- Consumers: `command grep` over the 45-repository snapshot found no use of
  the removed fields; `mctx.NewUser` is used in jagent and worldline tests
  and is kept.
