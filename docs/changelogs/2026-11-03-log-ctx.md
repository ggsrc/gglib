# fix(zerolog/log): Ctx never drops events silently and binds the context

Tracking: alva-ai/mono-meta#1115 (gglib, per-module PR). Stacked on #31.
Review problem 4 ("logs are silently lost"), observability ZL-1 and ZL-3.
Independent of the G5 format and export decisions (G9–G11).

## 1. Current state

- `log.Ctx(ctx)` was `zerolog.Ctx(ctx)`: with no logger in ctx and no
  `DefaultContextLogger`, zerolog returns a disabled logger. Only gglib
  `app.Start` sets the default, so alva-gateway (318 `log.Ctx` calls) and
  trex dropped those logs, as did gglib's recovery and error-log
  interceptors in any process that builds servers before `InitLogger`.
  alva-backend, jagent and worldline each carry a workaround.
- The returned logger was not bound to ctx, so hooks could not read the span
  (no trace id on OTLP logs unless the ctx logger was bound by hand).

## 2. Behavior after this change

- `log.Ctx` returns the ctx logger, else `DefaultContextLogger`, else the
  global `log.Logger`; the result is bound to ctx.
- Consumer impact: services that lost these logs start emitting them (more
  log volume in alva-gateway and trex, at the levels the code asks for).
  Callers only use `.Error/.Warn/.Info/.Debug/.With/.Err/.GetLevel` on the
  result (census of the 45-repository snapshot); nobody mutates it in place
  with `UpdateContext`, which would now affect a copy.

## 3. Decisions

- A context logger at level Disabled is treated like "none configured".
  zerolog gives no other way to tell its fallback apart.
- One small allocation per call for the ctx binding, the same as rick's
  `logger.Ctx`.
