# fix(metric): report bind failures, safe Stop, default port, tests

Tracking: alva-ai/mono-meta#1115 (gglib, per-module PR). Stacked on #31.

## 1. Current state

Review findings (lifecycle MET-1, MET-2, MET-5, MET-7), all proven:

- `Start` returned nil before listening. A taken port was reported only by
  the first `OK` call; later calls returned nil, and if nobody called `OK`
  the goroutine blocked forever.
- `Stop` before `Start` dereferenced a nil server. `app` calls `Stop` when a
  resource fails to start, so a resource failure crashed the process
  (APP-2).
- `NewWithOptions()` without `WithPort` listened on port 0.
- No tests. (`RecordEvent`, MET-3/4, was removed in #29.)

## 2. Behavior after this change

- `Start` binds synchronously and returns `metric: listen: …` on failure,
  then serves in the background. A second `Start` returns an error.
- `Stop` is a no-op when the server never started.
- `OK` returns a serving error on every call (sticky).
- `NewWithOptions` defaults to port 4014 (`DefaultPort`). `Addr` reports the
  bound address (useful with port 0 in tests).
- Unchanged: the default Prometheus registry at `/metrics`, port 4014 and
  `METRIC_PORT` — dashboards, alerts and KEDA depend on them (G5 report,
  requirement R12). `New` still panics on unparsable environment values
  (its signature is used by services).

Consumer impact: alva-backend's worker and alva-im-bots already check the
error from `Start`; a taken port is now logged by them instead of being lost.
